Privacy Policy

Effective and last updated: October 18, 2026

1. Who we are

ATLAS MEDIA (“the application”, “we”) is a private content-production and publishing automation tool developed and operated by an individual (“the operator”). It runs on the operator's own computer and is used only with the operator's own Google account and the operator's own YouTube channels. It is not offered to the public, has no public sign-up and no other users. Contact: cryso369@gmail.com.

2. Google user data the application accesses

The application accesses Google user data only after the account owner grants permission on Google's consent screen, and only through the YouTube Data API (v3) and the Google Drive API (v3). It requests exactly these OAuth scopes:

ScopeWhat the application does with it
https://www.googleapis.com/auth/youtube.upload Uploads finished videos, with their title, description, tags, category and language, to the authorised channel (by default with private visibility), and sets the video's thumbnail.
https://www.googleapis.com/auth/youtube.readonly Reads the authorised channel's identifier and title, so that uploads go only to the intended channel; reads the channel's upload-eligibility status; reads the metadata and status of a video the application uploaded (title, description, visibility, whether a thumbnail is set) to verify the upload; and reads the channel's most recent uploads (at most 50 entries: video ID, title, publish time, visibility) to detect an upload that may already exist before trying again, so that the same video is never uploaded twice.
https://www.googleapis.com/auth/drive.file Creates an archive folder structure and uploads backup copies of finished videos and related production files into it; reads back the name, size and checksum of files the application itself created in order to confirm each copy is complete; and reads the account's total and used storage quota to check that there is room. This scope gives access only to files and folders created by the application — it cannot see, read or change any other file in the account.

The application does not access email, contacts, calendar, photos, other Drive files, or any other Google service. It does not read comments, subscribers, analytics or revenue data. It does not edit or delete existing videos and does not delete anything from Google Drive.

3. How the data is used

Google user data is used only to provide the features described above: publishing the operator's own videos to the operator's own channels and keeping verified backup copies in the operator's own Drive. It is not used for advertising, profiling, analytics, machine-learning training or any other purpose, and it is not sold.

4. What is stored, where, and for how long

  • OAuth credentials. After the account owner approves access, Google issues a refresh token (and short-lived access tokens). They are kept in a local file on the operator's computer, written so that only the operator's computer user account can read it, and excluded from the project's version control. They are used only to call the APIs listed above and are never printed or sent anywhere except to Google. They are kept until the operator deletes the file or re-authorises, which replaces them. Google may also expire or revoke them on its own.
  • Local publishing records. To avoid duplicate uploads and to keep an audit trail, the application stores on the same computer: the video ID and URL, the channel identifier and title, upload and verification timestamps and the chosen visibility. For the Drive backup it stores the IDs, names, sizes and checksums of the files it created. These records are kept for as long as the operator keeps the project's files; they are not deleted automatically.
  • Content in Google's services. Uploaded videos remain in the YouTube channel and backup copies remain in the Drive folder until the account owner deletes them in YouTube Studio or Google Drive. The application never deletes them.
  • No server of our own. The application has no web server, database or cloud back end that receives Google user data. Data travels only between the operator's computer and Google, over the encrypted connections the official Google client library uses.

5. Sharing and transfer

We do not share, sell, rent or transfer Google user data to anyone, and no person other than the operator reads it. The application also uses unrelated services to produce content (for example text-to-speech and image generation); those services receive only the operator's own scripts and image descriptions, never Google credentials or data obtained through Google APIs.

6. Google API Services User Data Policy

The use and transfer to any other app of information received from Google APIs will adhere to the Google API Services User Data Policy, including the Limited Use requirements.

7. Revoking access and deleting data

  • Revoke from your Google account (immediate). Open myaccount.google.com/permissions, choose ATLAS MEDIA and select “Delete all connections” / “Remove access”. The application's tokens stop working at once and it can no longer reach the account. The application does not need to be running for this to take effect.
  • Delete the local credentials. Deleting the token files on the operator's computer removes the application's stored access; the application then cannot call the APIs until the account owner approves it again.
  • Delete the data it created. Videos can be deleted in YouTube Studio and the archive folder in Google Drive. Local publishing records can be deleted by deleting the project's state files.
  • Ask us. You may also write to cryso369@gmail.com to ask what is held about you or to request deletion.

8. This website

This website is a static page hosted on GitHub Pages. It sets no cookies, loads no third-party scripts, fonts or trackers and has no forms. As with any web host, GitHub may process technical request data such as IP addresses under its own privacy statement; we receive none of it.

9. Security

We take reasonable care of the data described above: credentials are stored in an access-restricted local file and kept out of version control, and the least-privilege Drive scope (drive.file) is used instead of full Drive access. We cannot guarantee absolute security, and this policy makes no claim of any external certification or audit.

10. Children

The application is not directed to children and does not knowingly process children's data.

11. Changes to this policy

If the application's use of Google data changes, this page will be updated before the change takes effect, and the date above will change.
